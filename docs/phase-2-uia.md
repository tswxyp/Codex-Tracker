# Phase 2 实机 UI Automation 报告

2026-11-18，Windows 11 Pro 25H2 x64，OpenAI.Codex 26.1111.2228.0，单显示器 1920×1080，96 DPI。数据来自运行中的正式侧栏、正式目录的已提交 WAL 和独立 Tracker 统计库。实机探针只输出计数与矩形。下列数量对应各自采样时刻。

| 场景 | 观测和结果 |
| --- | --- |
| 窗口身份 | 通过窗口类、可见性、前台句柄与 Windows 应用包族绑定。实际宿主为包内 ChatGPT.exe。用 Codex 的「文件 → 新建窗口」实际打开第二窗口，探针取得 12 个几何可见行、11 个匹配及 4 个行内标签。关闭这个空窗口后原窗口恢复，未中止进行中的工作。完整退出并冷启动同一 Codex 进程仍待独立环境复验。 |
| 侧栏及当前聊天 | 先发现左面板，再缓存其 Control View 子树，检查 List → ListItem → Group → 可 Invoke 的 Button。标题来自 Name，当前行来自 ARIA 的 current=page。一次最大化采样有 19 个结构候选，18 行通过视口裁切，1 行为当前页，17 行有唯一目录映射和本机统计。新建空窗口当前行计数为 0。 |
| 滚动及虚拟化 | 实际从标签位置滚动列表并回滚。一次自动探针从 18 行变为 19 行，18 个标题进入视口、17 个离开。标签跟随新行，悬停框更新。自动化另用相同矩形配两个线程 ID 验证复用。实机观察到可见集合替换，未证明这一版 Chromium 在该动作中重用了同一个元素对象。 |
| 折叠与展开 | 操作原生按钮后，收起状态测得 0 行、0 标签、0 详情。展开后重新取得 18 行和 1 个当前页，稳定画面恢复标签。 |
| 切换聊天 | 在已有标签覆盖的行内位置点击，实际打开另一聊天，工具栏标题与选中行随之改变。回到原聊天后重新识别当前页。 |
| 同名 | 同一标题在本地有多个 ID、跨主机重名、旧索引冲突和同屏重名均以自动断言验证。实际目录的解析和统计基于所有主机候选，只有唯一且状态有效的 local 记录能继续联查。当前布局 18 行中有 1 行未获得唯一有效映射。未以其余 17 行作为人工标注的准确率。 |
| 最大化和还原 | 实机原窗口还原后取得 12 行、1 个当前页、11 个匹配、4 个标签，原生操作区 22/22 点命中 Codex。再次最大化后重新取得 18 行。 |
| 更新后重新定位 | 在实际 UIA 树禁用优先的面板选择条件，按 navigation 语义重新发现，取得与正常选择相同的标题、边界与当前页集合。真实跨版本升级未在本机执行。未来版本若改变包身份或同时删除两种导航证据，标签会停显。 |
| 多屏与 DPI | 本机实际为 100%。自动布局测试覆盖 96、120、144 DPI，各自在虚拟屏原点 −1920、0、1920 验证行内避让与详情工作区裁切。双物理屏拖动、125%/150% 的系统字体渲染及混合 DPI 切换仍待实机。 |
| 主题 | 实际 Codex 为浅色。测试窗口实际绘制明、暗两套分层窗口配色。产品在行左侧取背景亮度选择颜色。Codex 深色主题联测仍待进行。 |
| Windows 10 | 尚无 Windows 10 实机结果。 |
