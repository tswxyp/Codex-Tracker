# Phase 4 成本核算使用手册

## 启动

Phase 4 沿用自托管 Tracker 账号、HTTPS 服务和 PostgreSQL。首次部署按 Phase 3 运行手册配置证书、邮件、数据库角色、密钥环和安全目录。对现有实例先备份数据库和独立撤销记录。停用旧 API，使用原配置、原 epoch 和迁移角色运行 `dotnet Tracker.Server.dll --migrate`，再以受限运行角色启动新发布目录中的 `dotnet Tracker.Server.dll`。正常升级沿用原 epoch，历史备份回退才需要换代。部署者使用自定义授权规则时，需给运行角色新表读写权限；标准部署已设置默认授权。

打开实例的 `/costs`，用浏览器登录。Windows 客户端需要 x64 .NET 10 Desktop Runtime。解压 Windows 包后，`tray/CodexTracker.Tray.exe` 负责侧栏与本地 Worker，`sync/Tracker.Sync.exe` 负责授权与同步，二者可分别启动。系统托盘菜单中的“成本核算”打开当前 Tracker 服务的费用页。两项可执行程序使用原来的本地数据目录。

```powershell
$sync = '.\sync\Tracker.Sync.exe'
$db = Join-Path $env:LOCALAPPDATA 'CodexTracker\tracker.sqlite'
& $sync login 'https://tracker.example.org:8443' '笔记本'
& $sync threads $db
& $sync allow $db '替换为本机设备根ID' '替换为线程ID'
& $sync sync
& $sync costs
& $sync watch
```

已有有效授权的账号可从 `sync` 开始。需要本机试用时选择脱敏测试库。同步范围、私有 CA、离线退出和备份恢复见随包的 Phase 3 手册。自定义 `--state` 会隔离同步状态；托盘读取当前 Windows 用户默认同步目录。

## 内置个人 Codex 权重

新版服务端的新建账单预填 `codex-personal-20261119`。这套权重按同一张参考表重估所选账期，采用个人 Codex 的标准模型权重和套餐内速度倍率。已存账单继续使用各自选择的版本。自定义权重请另取版本名。新版同步程序可传递明确的 Ultrafast 档位。账期完整性或速度依据不足时，服务端保留待核算；本机悬停仍可展示标准速度的 Credits 参考值。[权重来源](https://learn.chatgpt.com/docs/pricing?codex-pricing-plans=individual#token-rates)

## 手工录入

1. **订阅账单。** 选择计划、当地账期首日和结束日。结束日不含在账期内。按实际支付凭据填写原币金额与人民币金额，选择用于 API 比价的币种和整期权重版本。人民币账单两列金额须一致。确认所有设备及其他用量来源已覆盖后才填写“覆盖至”，使用 UTC。两台机器登录同一账号即可维护同一 Billing ID。现有用量流按账号划分，可以登记各自实付的重叠账单；重叠期间先保留待核算状态，避免同一批账号用量被重复分摊。
2. **价格与权重。** 每行指定模型、单位、适用速度、UTC 生效区间和四类单价，单位均为每百万 Token。价格行记录 HTTPS 来源。权重行的单位与账单中的权重版本对应。未知类别留空，有证据确认免费才填零。只有确有跨档位依据时才选“各档位通用”。模型或速度有争议时会保留缺项。可载入已核对的 GPT-4.1 标准文本 API 参考价，每百万普通输入 2.00 美元、缓存读 0.50 美元、输出 8.00 美元；缓存写缺价。参考价须由用户保存，默认从核对日起生效。其他模型可按各自公开价格录入。[GPT-4.1 模型价格](https://developers.openai.com/api/docs/models/gpt-4.1)
3. **Credits 凭据。** 录入脱敏凭据引用及实际覆盖区间。官方实扣分项逐行填写 `线程ID=数量`。只有明确无法归入具体线程的数量才填 `@pool=数量`。账期、截至时间和分项合计与官方总量均相符时使用 OFFICIAL。余额观测、生命周期估算及缺少分项的实扣凭据可保存对账。若实扣证据不足，整期按同一权重版本尝试 ESTIMATED 分摊。
4. **重置记录。** 选择所属账单、发生时间和类型，填写脱敏的唯一凭据引用。免费 Global Reset 填零，付费重置填实付金额，未知原因与未知金额可留待核对。重置前后额度可留空。重置对订阅支付和期间边界无影响。
5. **核对与修订。** 费用页按线程显示 API 等效已知小计、Credits、账期资源占比及订阅分摊。任务组和项目汇总复用同一份分摊明细；没有唯一项目归属的金额进入未归属项目池。“保存本次核算快照”记录当时的数据与规则版本。后续修改在“选择已有记录进行修订”中完成；原快照仍能单独查看。账单明细和快照属于本账号。

## 如何解释结果

- 普通输入扣除缓存读。缓存写为正时，依据价格来源选择“已包含在输入”或“单独计量”。分类不明时保留可确定的分项。推理 Token 包含在输出计价内。实际有用量的类别缺价时显示 PARTIAL 或 UNKNOWN。
- API 等效估算使用规范响应及有证据的快照增量。订阅分摊使用实际账单和同口径 Credits 占比。实际现金支出只取原账单及有支付依据的其他支出。
- 全部已知设备须至少完整同步到核算截至时间。已报告的未解决来源会阻止分摊。断网电脑的未来补传无法由服务端预知，故账期还须人工确认来源覆盖。分母为零、时间无法归期或整期权重不足时，页面列出待核算原因。
- 当前账期有已确认的截至时间时，可以显示暂计比例和暂计分摊。侧栏在成功同步后读取账号、设备根和线程均匹配的本地缓存，悬停显示统计截至和同步时间。尚未同步费用、已知有待传操作、账期已结束、无账单或已退出账号，会回到待计算状态。
- 费用页可查看由本人登记的所有账期。历史缺少速度的记录保持未知。旧快照发生时间仅在所有有效来源给出一致时间时用于归期。模型价表采用每百万 Token 的固定四类费率；阶梯价、长上下文差价或优惠折扣需要相应证据与适用规则，不能直接套用标准报价。

## 构建及复验

Windows x64 从源码执行 `scripts/build-phase4.ps1`。产物在 `artifacts/phase4`，其中两个 ZIP 分别包含 Windows 程序和服务端。源码测试使用 Phase 3 手册中列出的测试工具及已发布的 Phase 2 Worker。设置 `TRACKER_SERVER_DLL`、`TRACKER_SYNC_DLL` 为解压后的程序集路径后，运行 `python -X utf8 -B tests/test_phase4.py`。可设置 `TRACKER_COST_DISPLAY_DRIVER` 指向最新构建的 Tracker.Tray.Tests.exe，附加验证真实托盘文字格式化与退出隐藏。安装 Python Playwright 后可用 TRACKER_TEST_BROWSER 指定 Chrome 或 Edge 可执行文件，复验登录、账单录入、价表保存和窄屏布局。升级用例使用原 Phase 3 服务端发布目录。
