# Windows 11 笔记本实机补验

把测试 ZIP 复制到笔记本，**先全部解压**。双击同目录的 `CodexTracker.Tray.exe`，再打开 Codex 并展开左侧列表。需要 Windows x64 和 .NET 10 Desktop Runtime x64；如果系统提示缺少运行时，可从微软的 [.NET 10 下载页](https://dotnet.microsoft.com/download/dotnet/10.0) 获取。首次采集需要等待，先确认至少一行有标签或悬停明细。安装包内含既有候选版和只读采样入口，Tracker 会将本机采集结果保存在当前用户目录。

**先留一份基线。** 记下 Windows 当前主题、缩放、窗口大小和 Codex 包版本。双击 `sample-phase2-laptop.cmd`，在 8 秒内点击 Codex 标题栏将其置于前台，保持侧栏展开。脚本在 `evidence` 目录生成独立的 TXT，每次采样后将文件名与下面对应的测试编号记在一起。取悬停样本时，倒计时内将鼠标停在已有统计的行上。

| 测试 | 在笔记本上的动作 | 需要保留的证据 |
| --- | --- | --- |
| C1 Windows 11 原生深色 | 用 Windows 个性化设置切换为深色，确认 Codex 也实际变暗。分别查看短行、长行、歧义行，悬停、点击切换、滚动并返回。最后恢复原主题 | 深浅各一份采样；深色时 systemLight 和 appsLight 应为 0。人工记录可读性、错行、操作区遮挡和点击结果；截图先遮住标题、任务内容及路径 |
| C2 系统缩放 | 在“设置 → 系统 → 屏幕 → 缩放”分别选 125%、150%。每一档等待重排，分别最大化、还原、打开详情，测试原生点击和滚动；结束恢复原缩放 | 两档分别采样，目标窗口 Dpi 预期为 120 和 144。保留各档正常行、详情和命中计数，人工记录是否错位、越界、误点 |
| C3 完整退出与重启 | 在笔记本没有工作运行时，记录当前 Codex 主窗口进程号、一个已完成静态测试任务的统计与 Worker 数。保持托盘开启，正常退出整个 Codex，观察包内应用进程和浮层全部退出，再从开始菜单打开。从打开应用开始计时，到同一行统计恢复时停止 | 退出前后主进程号、退出期间进程/浮层数、恢复耗时、该静态任务前后数值和受管 Worker 数。重开后再保存一份采样；只关闭聊天窗口不足以证明冷启动 |
| C4 / C5 | 等笔记本有真实 Codex 版本更新时记录升级前后版本并复跑；有外接屏时选“扩展这些显示器”，保留屏幕拓扑、缩放，拖窗跨屏后在每块屏上采样 | 新旧两个真实包版本，或同时启用的两块物理屏、目标窗口各自 DPI 与实际命中。两项独立登记 |

**读数与交回。** `Labels` 和 `Details` 为当前可见标签及详情数，`PassThrough` 应等于两者之和；`ActionPass` 应等于 `ActionPoints`。成功样本需有可匹配行和实际被测窗口，分母为零、前台错误或缺少样本的场景继续待验。脚本采样不代替实际点击、滚动、外观和重启观察。只需交回对应编号、TXT、观察结果和已脱敏证据。Windows 10 另行实测。
