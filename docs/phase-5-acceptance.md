## 一笔合同的独立复算

两个同名项目保留独立 ID。第一项合同 1,000 元，10 月已收 300 元，11 月到账 600 元，12 月 1 日到账 80 元。查看 11 月账期时，实际到账 600 元，期末合同余额为 100 元。

| 11 月第一项目 | 金额（人民币元） |
| --- | ---: |
| 项目分到的订阅实付（100 元中的 75%） | 75.00 |
| 有支付凭据的重置 | 8.50 |
| 额外 AI 购买 | 20.00 |
| 人工、服务器、其他（100 + 10 + 5） | 115.00 |
| 现金成本合计 | **218.50** |
| 项目利润（600.00 − 218.50） | **381.50** |

另一个项目只有 11 元人工支出，利润 −11 元，利润率留空。剩余的订阅实付 25 元保留在未归属池。11 月账号现金成本为 254.50 元，净额 345.50 元。三笔响应按固定测试价表得 API 等效 0.094166 美元，仅进入参考栏。切换全部账期后累计到账 980 元，净额 725.50 元。

## 核验内容

- 分批回款、下期首日、历史合同余额、实际亏损、零到账、同一流水重复提交、作废及并发修订。测试数据库保存对应的各次修订。
- 使用手工官方实扣分摊和估算权重两种数据。有未核实用量时还原已付订阅额并保持项目利润待核算。模型报价单列。条件满足时按实付计算 Token 均价。
- 同一支付凭据先录入额外支出、后出现在重置账本的情形，现金只计一次。外币重置无人民币凭据时留待核算。重置修订后拒绝旧版本归属。
- 同名项目、会话 ID 与线程 ID 关联、更换归属、两台逻辑设备重报、按设备、项目、模型、日期、最低 Token、费用和活跃时间筛选。
- 两个线程并行、暂停与跨账期区间裁剪。两个各自有活动的线程在所选项目合并为两小时，到账 400 元对应每个已核实活跃小时 200 元。
- 从原 P4 发布包建库并写入已有成本快照，重复执行 P5 迁移后核对实例 epoch、原数据及独立 finance schema。跨账号项目或账期请求被拒，设备变更流只含项目名及归属。
- Chrome 实际登录、创建项目和回款、浏览利润报表、下载工作簿，并检查 390 像素窄屏。CSV 对可能被识别为公式的名称转义，工作簿将名称保存为文本，金额保存为数值。

## 试用范围

项目正式收付以人民币录入，重置保留原支付币种和人工确认的人民币折算。利润采用当前归属与最新修订重算；已导出的文件可用于对照先前版本。未知覆盖可能使项目利润待核算。每千万 / 亿 Token 的均价属于整笔订阅均由已采集 Codex 使用时的账期指标。对使用 Ultrafast 的任务，继续核实速度与权重来源。

此次为本机自动化及浏览器验证。两台物理 Windows 电脑联测、Docker Compose 实际启动与之前登记的 Phase 2 实机补验保留原状态。
