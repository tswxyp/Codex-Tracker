## 本版本的实现选择

- Windows 端以独立 CLI 提供 `watch`。用户可单独控制采集与同步。状态库按实例与账号分区，Outbox、来源版本和游标在本机事务内写入，刷新材料与设备签名密钥由当前 Windows 用户的 DPAPI 保护。源文件身份变化或历史回退时隔离该范围，其他已确认的队列仍可提交。
- 服务端采用 ASP.NET Core Identity、OpenIddict 设备流、PostgreSQL 事务和租户行级策略。项目、设备和观测均从授权解析账号。服务端分别持久化操作回执、来源和规范账项。含冲突或归属不明的计量独立保留。
- PostgreSQL 实际使用 `account_stream`、`device`、`grant_state`、`observation`、`resource`、`change_log`、`receipt`、`snapshot` 和 `snapshot_page`。线程、事件、计时、任务组、项目及冲突共用带版本的 `resource` 表。数据库结构见[迁移 SQL](../server/Tracker.Server/sync-v1.sql)，客户端表见[同步库迁移](../client/Tracker.Sync/Sidecar.cs)。
- 网页账号操作使用 `/Identity/Account/` 下的表单。设备管理在 `/devices`，按项目、组或模型查看用量在 `/dashboard`。当前实现逐线程授权，注册由部署者开关控制。全库自动选择、单独的管理中心 GUI、备份服务和托管运营均未列入交付。
- 首版按单个 API 实例部署，直接在 Kestrel 终止 TLS。每次回滚数据库均须换代，由运营者核实账号，通过验证邮箱找回密码并重新配对。独立目录中的撤销记录须随最新可信副本保管。缺失时使用冻结恢复。记录及其摘要同时回退到旧副本属于部署者备份边界。

## 环境与数据核对

最终发布包测试通过 **11/11**，用时 **153.129 秒**，包括 10 项 HTTPS/PostgreSQL 集成测试和 1 项离线冻结库核对。PostgreSQL 归档实测大小为 272,069 字节。在隔离库还原后先查得 1 笔、35,977 Token；经邮件重置、设备重新授权及客户端对账，补回 78,171 Token，恢复 3 笔、114,148 Token。从开始还原到统计核对完成为 9.7 秒，使用本机临时数据库、临时 SMTP 和自动化批准流程。[最终测试输出](../artifacts/phase3/integration-run.txt)

Windows 11 x64，build 26200.9974，.NET SDK 10.0.404，ASP.NET Core 10.0.15，PostgreSQL 17.12。两份设备状态、绑定密钥、Outbox、只读输入库均独立。自动化在同一 Windows 用户下启动不同进程。网页测试通过实际 HTTPS 表单、邮件验证链接和防伪令牌完成授权。

复测可使用 PostgreSQL 完整安装的 `bin` 目录设置 `TRACKER_PGBIN`。若使用仅含服务器的精简发行包，还需提供对应版本的 `pg_dump.exe` 和 `pg_restore.exe` 并将其目录设为 `TRACKER_PGTOOLS`。本次使用 17.12 的完整客户端工具执行备份归档与恢复。
