# Phase 3 自动化验收设计

以下为设计时冻结的验收用例和从脱敏夹具独立复算的期望值。候选版的已执行步骤、结果及剩余条件见[开发与实测报告](phase-3-implementation.md)。Phase 2 实机补验使用[单独登记表](phase-2-compatibility.md)。

## 固定输入和判定口径

使用两个相互隔离的 Windows 客户端 A、B（独立采集根、用户凭据和同步库），测试账号 U、V，一套可清空的自托管 HTTPS API、真实 PostgreSQL 及测试邮件收件器。独立进程驱动已发布 Worker 写 v2；在进程和网络边界控制停机、延迟、丢响应、重排和重复。用受限账号查询云端规范事件、来源、回执和变更组，用本机查询核对清单/游标及用户可见汇总。CI 可使用两台独立 Windows 测试机或 VM；发布验收再用两台独立安装的 Windows 电脑走通授权和离线恢复，记录系统、客户端和服务端版本。

[真实结构脱敏样本](../tests/fixtures/turn.jsonl) 的三个响应依次记为 R1、R2、R3。总量分别为 **35,977、37,963、40,208**。整组输入 109,911、输出 4,237，**合计 114,148**；其中缓存读 106,368，缓存写 0，推理 49。在 A、B 同时提供全组响应时，预期为 6 个设备来源、3 笔规范响应和 114,148 Token。另有核对、会话和计时观测，单独按类型查询。CI 以固定预期或独立参考实现判定，禁止用被测汇总生成期望值。

键编码固定向量：账号 `00000000-0000-4000-8000-000000000001`，线程 `thread-A`，响应 `response-1`，按[协议编码](phase-3-data-sync.md)得十六进制 SHA-256 `c937a11d7a7f50b7f4a635941ddff2f7175bb9f8db09dca0d8910e3bafad3764`。切换设备保持同键，变更账号或线程得到不同键。

## 必测的 12 个业务场景

| 编号与场景 | 初始数据与动作 | 可机器判定的通过条件 |
| --- | --- | --- |
| A01 两台设备登录同一账号 | U 验证邮箱，分别在 A、B 完成浏览器批准；改名 A；推进服务端测试时钟及发心跳 | 同一 sub、2 个不同 Device ID 和独立 grant；列表含名称、OS、版本、注册时间、Last Active、Last Sync；无初次同步时 Last Sync 为空。B 超过 3 分钟显示离线，A 心跳在线。改名不改历史键 |
| A02 两台设备离线采集 | 已授权后阻断两机到服务器的网络，两机均完整采集 R1–R3，结束进程并重开 | 各自本机 114,148；选定范围中各 3 条响应待传，云端新增响应 0；本机采集与列表仍可用，服务端 Last Sync 不前进 |
| A03 网络恢复后补传 | 延续 A02，先只放行 B，再放行 A，走完 push、pull、complete；以相反顺序复跑 | 第一次补传云端已归属 114,148；第二次仍 114,148；6 个响应来源、3 笔规范响应。两机缓存相同、待重试数 0，Last Sync 更新 |
| A04 同一事件重复上传 | 相同 op 并发传 10 次；提交后丢 ACK 再重发；另换 op_id 上传同来源/同版本；改载荷复用原 op_id | 首个 op 唯一持久回执；同一来源有效版本仅一份，同键账项仅一笔；响应统计总量无变化；复用 op 异载荷明确 OP_ID_REUSE |
| A05 同一会话跨设备恢复 | 同 Session/Thread，A 有 R1、R2；B 有 R2、R3，离线后交错补传，并使 B 的显示时钟有偏移 | 两机本机分别为 73,940、78,171；云端 4 个响应来源、3 个事件，总计 114,148；R2 只计一次；同号 Session 的独立子线程仍能区分 |
| A06 同名不同会话 | 生成两个真实结构的不同 Session/Thread，本机标题相同。同步后人工将二者归入一个组，再调整项目 | 云端保留两个会话，两组事件各自存在；人工操作前关联数 0，之后组有两个成员和显式项目。名称相同不会合并，关联操作前后规范用量相同，请求内无默认标题 |
| A07 设备解绑 | A、B 均传完；A 断网积压新事件。在 B 对应的网页登录 U，解绑 A，使用 A 旧访问/刷新凭据尝试读写、心跳、快照 | 成功撤销后的请求全部拒绝；A 分区冻结、B 继续同步；历史规范总量、A 既有来源保留。再次配对分配新 Device ID |
| A08 账号切换 | A 以 U 离线积压 R1 后退出并登录 V；延迟 U 的旧网络回调到 V 活动时返回；再切回 U | V 服务端和本机副本中 U 的来源、项目、游标数均为 0；V 的范围初始为空；旧回调不能更新 V 的凭据/队列；U 经核实恢复后只上传一次，退出句柄只可撤销 U 的旧 grant |
| A09 云端数据恢复 | U 上传 R1 后备份；A 再上传 R2、R3 并收到 ACK；同时修改项目并解绑 B。回滚数据库至备份，按恢复规程换代 | 旧 epoch/令牌被拒；B 不因回滚复活；A 重新授权后从新快照发现两条已 ACK 来源缺失并补传，恢复 114,148。项目旧意图列为恢复差异，提交前不覆盖现值 |
| A10 断网和服务端异常 | 在事务提交前、提交后发 ACK 前、客户端下载页写盘时分别强停；注入 DNS 失败、429（含 Retry-After）、503，再恢复 | 事务无半份账项；重试遵守服务端最短等待并有上限；ACK 丢失仍只计一笔，游标与缓存同进同退；重启收敛到基准摘要，Last Sync 仅在成功轮次更新 |
| A11 并发修改项目资料 | 两机由版本 7 离线各改一个不同名称，恢复后并发提交，再以当前版本解决冲突；另跑删除与改名竞争 | 一个操作成功到 v8，另一个返回同一可查询 conflict，含基准、当前及提议值；解决后版本只增一次，两机收敛；旧改名不能复活已删除项目 |
| A12 不同用户数据隔离 | U、V 刻意使用相同 Session、响应 ID、项目 UUID；交换分页/快照票据、伪造目标账号、跨账号关联成员，复用同一数据库连接池 | 两个账号各有自己的 114,148，互相数据可见数/写入数均为 0；跨租户外键被拒、访问非本人资源返回 404 或无授权；错账号的 read、push、pull、conflict、device 管理都无法泄露数据 |

## 统计、安全和部署的回归条件

| 编号 | 注入条件 | 通过条件 |
| --- | --- | --- |
| E01 快照及反证 | 在真实结构夹具中重复正值本次量且保持累计不变；A 只上传旧快照证据，B 后传同段响应；再换顺序 | 重复累计贡献 0；可证响应保留一笔；已入账但失去依据的旧增量撤回。缺少跨设备流/序号/基线的旧项进入 PARTIAL 或 UNKNOWN，顺序不影响最终合计 |
| E02 分叉和来源撤回 | 采用[子代理夹具](../tests/fixtures/child.jsonl)及经标注的继承旧快照，分别延迟父线程、撤回一个重复来源、重复及乱序发送 retract | 父、子关系与独立工作保留；继承副本不双计；撤掉 A 时 B 的有效独立证据仍支持账项。晚到的旧版本不能复活已撤回条目 |
| E03 同键异值与未知 | 在 B 修改 R1 用量并保持 input+output=total，response_id 不变；另测一致用量的模型分歧、缓存字段 null | R1 异值留 conflict，精确小计只含 R2+R3=78,171；重复传输不制造额外冲突；模型争议单列 UNKNOWN；缺失缓存字段保留 null |
| E04 多机耗时 | 上传部分重叠的已证执行区间、暂停和未知区间；加入两个来源对同一段的相反证据 | 例如总区间 [0,100) 秒，两段活跃 [0,20)、[10,30)，暂停 [40,60)，得活跃 30、暂停 20、未知 50；新增明确暂停证据 [10,20) 与活跃冲突后活跃 20、暂停 20、未知 60；总历时恒等于三个互斥分量之和 |
| E05 游标与快照 | 同账号两个事务并发，一个延迟提交；下载时产生新变更；游标超期；下载半个快照时杀进程或改动一页 | 每个已提交变更恰可到达一次投影，没有越过未见提交；页摘要错误拒绝切换；旧缓存和本地 Outbox 完整；恢复后增量追平到 head |
| E06 白名单与禁止上传 | 在原始聊天、默认标题、提示词、回复、代码、OpenAI 凭据位置、路径、未知扩展、raw_metering、质量说明中分别放无效测试哨兵；另输入允许的任务组名 | 捕获 HTTP 正文/错误、代理/API 日志、冲突、数据库所有同步列、导出及恢复后的云端库，禁止哨兵出现次数均为 0；人工维护名称恰在允许字段出现；未知键和伪装的自由文本模型被拒或归 UNKNOWN |
| E07 身份与失效 | 注册/验证、改密、找回、反复请求未知邮箱、过期/重用验证链接、拒绝设备码、刷新重用、缺少 CSRF、离线退出后联网 | 已验证用户才能批准；过期及重复链接无状态变化；改密/找回使各旧授权失效，离线退出重连后远端撤销得到确认；日志中口令及令牌为 0 |
| E08 大库与源故障 | 读取 v2 期间中断、将原库临时离线、恢复较旧本机备份、重开旧版/更高 schema 库；测试中一次改变投影而不新增物理行 | 无批量误撤回；受信源恢复后可重新差分；修订与撤回均送达；已确认高水位不会被旧清单覆盖。记录首次全扫时间、WAL 峰值及采集延迟，与同机冻结基线对照 |
| E09 自托管与升级 | 在干净主机从固定版本源码/镜像部署，阻断通向开发者域名的网络；使用自选 HTTPS、PostgreSQL、SMTP；升级和还原备份 | 两机注册、配对、同步、找回均可用；无中心服务调用；数据、密钥及安全记录按恢复方案可分别还原，升级前后六字段合计相同；记录实际 RPO/RTO 和缺口 |
| E10 原功能及幂等升级 | 在获准实施后用隔离库重新运行现有 Phase 1 / 2 自动化回归，并对脱敏夹具执行重扫、重登和客户端升级；用冻结副本验证源数据 | 本机基线断言通过，原始文件哈希一致；U 的规范事件仍为 3，六字段和与上表一致。Phase 1 既有实样中的 58,814,396 个归属待核实 Token 均不能被提升为精确任务用量 |
| E11 重放属性 | 对固定数据在相同版本约束下随机排列两机来源、重复操作、崩溃点与撤回，保留随机种子；从空云库、非空云库各跑 | 比较规范事件键/字段/状态、当前来源及未决冲突集合，两客户端与独立参考结果一致。允许回执时间/提交顺序不同；跨账号从同一源 ID 计算得到不同规范键 |
| E12 撤销竞态和灾备缺证 | push 与解绑争同一账号流；再恢复到解绑前，刻意缺失独立撤销记录或丢失原机绑定证明 | 只有在撤销提交前获准的事务可以生效；缺少撤销证据时保持冻结，旧凭据成功数为 0。无法证明旧设备身份时新配对，模糊历史不自动归并 |

验收报告需逐项附运行版本、环境、样本哈希、预期/实测、失败复现种子及脱敏证据。A01–A12 和 E01–E12 均应通过；因环境缺失的项逐项标为待验或受阻。任何跨账号泄露、禁止字段外发、重复记账或已撤销设备仍可同步，都阻断 Phase 3 签收。容量参数与备份目标须在实际自托管环境另列实测值。Phase 2 的主题、DPI、升级、多屏和 Windows 10 等结果只按其实机登记回填。
