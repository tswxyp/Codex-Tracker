## 实施顺序与数据结构草案

| 顺序 | 交付 | 数据与约束 |
| --- | --- | --- |
| 1 | API 等效成本 | 价表按模型、计价类别、速度适用条件、币种及生效区间保存单位价格和来源。逐个规范事件匹配发生时有效的价表；互斥拆分普通输入、缓存读、缓存写及输出。推理 Token 已包含在输出时只计一次。金额用定点数 |
| 2 | 订阅账单和重置记录 | 账号内账单使用稳定 Billing ID，同一订阅同一账期唯一。保存账期时区、起止、实付原币、币种、人民币金额及支付日期。重置单独登记类型、时间、来源、前后额度及现金影响；免费 Global Reset 的现金为零，沿用原 Billing ID |
| 3 | Credits 和订阅分摊 | Credits 记录保留账号、可证实的任务或账号范围、账期、单位、来源与规则版本。分摊明细按账单、任务或未归属池及核算版本保存。优先使用覆盖一致的官方实扣；需要估算时整期采用同一版本权重 |
| 4 | 结果展示与重算 | 展示 API 等效估算、订阅分摊、本账期资源占比及各自可信度。账单修订、迟到事件、撤回、价格或权重变更后可重算，并能追溯产生结果的输入版本 |

首个开发单元是价表和独立计价函数。Phase 3 部分旧快照的规范投影缺少发生时间，速度档位也可能未知。匹配所需字段缺失时保留已知小计与未知范围。[Phase 0 数据可得性](phase-0-survey.md) · [架构口径](../ARCHITECTURE.md)

## 首批验收标准

- 使用固定测试价表和脱敏响应独立写出金额期望值。两台设备重复上报相同响应只计一次；价格生效边界两侧按各自版本核算。
- 两个设备重复提交同一订阅同一账期，只产生一笔现金支出。跨账期任务按事件发生时间分段，缺时间的部分保持待核实。
- 用测试账单 100.00 元、同口径资源权重 2∶1∶1 验证两项任务及未归属池分别分得 50.00、25.00、25.00 元。另测分币余差，所有明细之和须等于实付金额。
- 已选范围尚有设备欠传、账期覆盖不足、分母为零或权重未知时，展示覆盖状态与待核算原因。仅有余额、限额窗口或官方界面生命周期估算时保留来源，避免生成任务级官方实扣。
- 免费 Global Reset 前后的事件归属同一账期，账单数量和实付金额保持一致。付费重置以支付凭据登记。缺少重置原因时保留 UNKNOWN。
- 混合已知和缺价事件时显示已知小计与缺价项，订阅现金与 API 等效估算分别核对。迟到、撤回、重复核算和跨账号隔离均须有自动化断言。
