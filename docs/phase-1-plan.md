# Phase 1 实施计划与验收口径

1. 建立 Windows 本地独立 Worker、数据库迁移和基础命令行任务列表。管理界面可作为独立只读消费者。
2. 自动发现活动与归档 rollout，按设备和输入根隔离来源。流式读取 JSONL/Zstandard，事务绑定进度及原始计量证据。截断、损坏和未完成行可重试。
3. 建立独立 Token Ledger。逐响应按逻辑线程和响应 ID 去重；旧快照只在可验证的基线与增量上作保守推导；重叠、缺失与冲突可追溯。按模型分组，缓存与推理不重复计入总数。
4. 从时间事件重建开始、暂停、恢复、完成和重叠区间。区分明确活动、已知暂停与未知时间。
5. 以脱敏实录驱动端到端测试，覆盖双扫、追加、截断、异常退出、两类用量差异、模型切换、子代理、恢复、设备隔离与尾行续写。另用独立解析器核对真实文件，并记录分母和缺口。

数据库设计先行。Device 定义来源命名空间；Project 预留本地引用；Session 保存逻辑线程、运行会话和父子关系；SourceFile 保存读取边界与解析上下文；Event 和 SourceRecord 分别保存逻辑事件及物理观测；TokenLedger 保存唯一可入账项及方法；ModelUsage 汇总六字段；TaskTiming 保存时间边界及各类时长；DataQuality 保存原始证据关联及原因。使用外键、唯一约束、线程/轮次索引及 SQLite user_version 迁移。原始计量字段独立保留，聊天内容、源码和凭据留在原文件。

验收时对同一冻结输入核对逐响应六个字段，分别报告响应计量正确率、可核对覆盖率、旧快照未知量和时间证据局限。重扫或异常重启后的已确认总量应与干净单遍导入一致。所有验证使用独立 Tracker 数据库，Codex 输入只读。
