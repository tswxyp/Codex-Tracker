## 统计如何展示

行内按可用宽度依次尝试 Token、模型、历时和成本状态的组合，短格式使用带 ≈ 的 K/M 数值。详情使用完整数字。“可归属 Token”含逐响应观测及常规快照推导，另列归属或字段待核实的账项。带星号表明有额外待核实量。仅有待核实用量时显示“Token 待核实”。输入、输出、缓存读写与模型分布都使用可归属范围；没有证据的值显示未知。详情区显示总历时、可证实的实际执行、暂停和未知时间。

使用 Phase 1 冻结样本独立回读，逐响应观测 7,211,991 加常规推导 7,518,825，行内可归属小计 **14,730,816**。另有 **58,814,396** 待核实，两者合计与验收库的 73,545,212 相符。账期资源占比、API 等效成本、订阅分摊成本均有名称并显示待计算，分别待账期分母、价表和账单规则具备后再接入。

## 验证结果

- 发布 Worker 运行原有 **20/20 项**端到端测试通过。Worker 源码和 SQLite v2 迁移无改动。
- Windows 侧栏测试程序运行 **29/29 条断言**通过，含真实样本小计、多主机及同名歧义、旧索引冲突、复用、DPI 和多屏几何、源文件保护、WAL 增量、深浅色分层窗与真实点击滚轮。
- 单独运行 **2/2 个进程级测试**通过。实际发布 Worker 与真实结构脱敏夹具验证暂停、跨进程保持暂停、恢复、Worker 崩溃后自动重启、托盘被终止后清理子进程，以及重新打开后已提交用量一致。整台托盘宿主被终止时，可重新打开程序或由用户启用的登录启动恢复。
- 实机额外运行 UIA 回退定位、滚动集合替换和生产覆盖 HWND 命中验证。在一个最大化画面，18 个可见行中有 17 个可显示详情，6 个有行内数字。悬停时 7/7 个覆盖窗口及 34/34 个原生操作采样点全部穿透。实际切换聊天、折叠与恢复、最大化与还原及第二个 Codex 窗口启闭均成功。

## 未完成的实机验收条件

1. 第二台显示器、实物跨屏与系统 125%/150% DPI。现有三档缩放及负坐标覆盖为几何测试。
2. Codex 自身深色主题、Windows 10、升级到另一真实 Codex 包版本。深色覆盖绘制与失去首选定位条件已有受控验证。
3. Codex 整个进程的冷启动/完全退出。这里验证了新窗口创建、销毁、前后台切换和原窗口重新定位，保留了承载进行中任务的进程。
4. 原生 UIA 未暴露稳定线程 ID。唯一标题加本地目录与同根设备是候选映射。遇到同名、缺索引证据、源库持续活动或行宽不足时展示覆盖率会下降。此次覆盖率不代表整机准确率。历史回填进行期间用量仍会增长。

建议在现有 Windows 11 环境进行用户试用验收，将上述项目列为扩大发布前的复验条件。阶段决策由用户确认。
