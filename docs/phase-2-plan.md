# Phase 2 实施计划与验收条件

1. 依据 Phase 0 的实机树定位包身份、列表、聊天按钮、标题、ARIA 当前页、操作按钮和可用区域。按前台窗口、屏幕物理矩形、UIA 命中及可见性裁切，重新枚举已实现的行。标题、数据源或布局证据不足时撤下标签。
2. 从正式目录读取包含已提交 WAL 的一致副本。在全部主机候选中做精确匹配，仅接受唯一的本地线程，并与当前数据根绑定的 Tracker 设备联查。后台刷新失败时撤销旧映射。
3. 展示数据按线程提供「观测、常规推导、待核实」三组 Token，行内可展示前两组的小计，详情保留六项计量证据中的输入、输出、缓存读写及模型分布。耗时取 TaskTiming 的总、活跃、暂停、未知及可信度。账期、价表、订阅账单缺失分别显示待计算。复用 SQLite v2，无新表或迁移。
4. 开发独立登录会话托盘宿主。管理现有 Worker 的运行、暂停、故障重启和退出。分层窗以不激活、鼠标穿透方式显示标签与悬停详情，缺少行内空间时仅保留安全的详情入口。
5. 以发布版跑 Phase 1 回归、真实目录核对、行匹配及展示测试、Win32 命中验证。验收逐项覆盖启停、滚动、收展、切换、当前行、重名、复用、窗口状态、多屏、三档 DPI、主题、穿透、版本变化、崩溃。注明样本、物理环境、受控环境与缺项，Windows 10 单列。交付后发送报告，等待用户确认。
