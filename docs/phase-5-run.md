# 项目财务使用与升级

项目财务由自托管服务端提供。沿用 Phase 4 Windows 客户端与 Tracker 账号。打开实例的 `/finance`，或在“用量统计”和“成本核算”中选择“项目财务”。

## 部署

新实例按 Phase 3 手册配置 PostgreSQL、HTTPS、账号邮件、密钥环和安全目录。已有实例先备份数据库、密钥和独立撤销记录。停止旧 API，解压 Phase 5 服务端到新目录，沿用现有配置和 epoch。使用迁移角色执行 `dotnet Tracker.Server.dll --migrate`，确认标准运行角色具备新表权限，再用受限角色启动 `dotnet Tracker.Server.dll`。服务端为依赖框架发布，需要 ASP.NET Core 10 运行时。原 Windows 采集、托盘和同步包可继续使用。

## 从第一笔回款开始

1. 打开“客户项目”，填写项目名称、客户、合同总额、状态和开始日期。已同步的项目可直接补录档案。完成项目时填写完成日期。同名项目按 ID 区分。
2. 在“任务归属”选择项目并创建任务组。将一个或多个已同步的线程 ID 或运行会话 ID 加入任务组。修订任务组会更新所关联会话的实时项目归属。可选择既有关联后解除或更换。同步设备只收到用户显式维护的项目名、任务组及归属关系。
3. 在“收支流水”逐笔登记回款、额外 AI、人工、服务器和其他实际支出，填写记账日、实付人民币和唯一凭据编号。支持分批回款、修订和作废，同一笔收付可用同一记录重试。合同总额仅用于计算合同余额。客户名称、金额和支付引用只保存在自托管账号的财务账本中。
4. 订阅账单和重置继续在 `/costs` 维护。付费重置从“重置归属”分配项目，外币填实付时折合人民币。支付凭据修订后重新核对归属和折算。免费重置现金为零。未归属支出单列汇总。
5. 在“利润报表”切换全部或单一订阅账期，按利润或到账排序，下载 CSV 或 XLSX。“任务记录”支持按日期、设备、模型、项目、Token、分摊及活跃时间筛选。设备和模型筛选用于选中线程，统计数为该线程跨设备去重后的合计。

## 指标

- 所有现金报表以人民币计量。项目利润等于本期到账减去本项目承担的订阅分摊和其他现金支出。API 等效按报价币种单列已知小计。
- 合同余额采用当前合同额减截至范围末日的累计到账，可为负值。到账为零时留空利润率及 AI 成本率。每小时到账用已核实活跃时段的并集，重叠子会话只算一次。
- 账号净额按到账减全部已知现金成本，含未归属池。有重置缺少金额或外币折算时，总览显示已知成本并将现金净额留空。若订阅分摊尚未核实，项目利润待核算，账号层仍可计入已付账单。
- 单账期按该订阅当地的起止日筛选现金流水，结束日不含。账期选择不会将合同总额截短。全部账期按流水 ID 只记一次。两个订阅日期重叠时，两份单期报表可能展示相同日期的流水，跨期总览使用“全部账期”。
- 回看旧账期时使用当前已登记的合同、归属及修订后流水重新核算。要保留当时的报表可导出工作簿。P4 已保存的成本快照仍可在成本核算页查阅。
- 每千万 Token 的订阅折算为当期实付人民币 × 10,000,000 ÷ 同期已核实 Token。每亿折算为其十倍。假设整笔订阅用于所选 Codex 来源，且当期全部 Token 由这笔订阅承担。已知有额外 AI 支付、未归属凭据缺少 Token、时段或覆盖不全时留空。这个指标用于比较账期，项目订阅费继续按 P4 的 Credits 规则分摊。
- P4 客户端对 Ultrafast 的独立识别仍待补充。遇到相关用量应核对官方实扣或适用速度权重；速度存疑时请保留待核算。客户可优先试用人民币账单和已核对的历史账期。

## 源码复验

运行 `scripts/build-phase5.ps1` 生成服务端 ZIP。将 `TRACKER_SERVER_DLL` 指向解压后的程序集，在 Phase 3 测试环境运行 `python -X utf8 -B tests/test_phase5.py`。设置 `TRACKER_TEST_BROWSER` 为 Chrome 或 Edge 的可执行文件可运行浏览器录入和下载测试。P4 升级测试需要工作区中保留原 P4 服务端 ZIP。
