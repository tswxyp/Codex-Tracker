# Phase 3 数据结构与同步协议 v1（设计稿）

读者可用本文跟踪一条响应从本机 SQLite 到两台设备共同可见的全过程。协议中所有写入按账号隔离，UTC 毫秒记录源时间，服务端提交序号记录同步顺序。[实施计划](phase-3-plan.md) · [API 与信任边界](phase-3-api-security.md) · [验收用例](phase-3-acceptance.md)

## 四种业务身份和三种幂等键

| 身份 | 生成与作用 |
| --- | --- |
| Device ID | 客户端在首次绑定某个 issuer 和账号时生成随机 UUID，经用户授权后登记。跨账号及重装默认生成新 ID。SQLite v2 的 Device 表标识采集数据根，与授权设备保留本地映射。 |
| Session ID / Thread ID | Session ID 是源运行会话标识；同运行会话可能关联主线程、子代理和分叉，每个逻辑线程使用源 thread_id。保留两者及有证据的父子/继承关系，禁止以标题、设备名或目录认定身份。来源缺失或标识冲突时进入待核实。 |
| Task Group ID | 账号内 UUID，用户手动把一个或多个运行会话或明确的线程关联到同一任务。组的汇总取成员账项的集合，并对执行区间求并集。归组不改写来源和事件身份。 |
| Project ID | 账号内 UUID，用户命名。一个项目可包含多个任务组；组可暂时没有项目。更名沿用原 ID；删除以墓碑传播，保留历史账项。 |
| op_id | 每个不可变写操作生成 UUID，超时用同一 ID 和同一载荷重试。一个 push 批次可含多个 op_id；换批次不产生新账项。 |
| observation_id | 每个授权设备对同一来源事实分配稳定 UUID，映射保存在本地清单中；每次修订或撤回递增 source_rev。数据库唯一键为账号、设备、observation_id。 |
| event_key | 同账号跨设备的规范事件键。响应使用账号、已证实的原属 thread_id 与 response_id，排除设备、时间、计数、文件路径和任务组；后四类信息分别用于核对或展示。没有可靠身份的观测允许无规范键。 |

云端根据白名单字段重算键。约定 SHA-256 输入依次为域标记（如 `ct.response.v1`）、账号 UUID 的小写标准文本、原属线程、响应 ID；每段使用 4 字节无符号大端长度后接 UTF-8。源 ID 保留大小写与原字节语义，空值与缺失不参与造键。账号、各类事件和键算法版本各有独立命名空间。观测载荷哈希使用版本化 DTO 的 RFC 8785 规范 JSON，毫秒、Token 和修订限在协议安全整数范围，拒绝溢出与重复 JSON 键；服务内部计数用 bigint，汇总使用更宽的精确整数。源时间和来源记录用于解释重放、检查边界并发现冲突；客户端时钟快慢不决定哪条计量获胜。

v2 的 `Event.id` 包含本机设备；逐响应 `logical_id` 由线程和响应构成，部分旧账项 ID 含本地事件 ID；`EventSource.source_record_id` 由文件、代际与偏移组成。三者均只在本地桥接时使用。跨设备来源关系通过多个 observation_id 指向同一 event_key 表示。[v2 结构](database.md) · [采集器](../client/Tracker.Worker/Scanner.cs) · [投影规则](../client/Tracker.Worker/Projection.cs)

## PostgreSQL 逻辑表

下表是拟议 schema。`a` 代表 account_id；除 Identity、部署控制与迁移表外，每张业务表都含 `a`，外键两端同时携带 `a`。逻辑 ID 即使为随机 UUID 也不跳过租户校验。时间列区分客户端的 occurred_ms 和服务端的 timestamptz。所有版本为正整数，删除以 deleted_at 或状态记录。运行角色启用强制行级策略，角色与连接池细节见安全设计。

| 表 | 主键、关键字段及关系 | 必需约束 / 访问路径 |
| --- | --- | --- |
| Identity 用户与框架附表 | 用户 UUID 即 a；标准密码哈希、安全戳、验证/锁定、注册时间、可选用户维护的显示名。框架管理 claims、登录与授权材料 | 规范化登录邮箱唯一；令牌、验证材料有用途及期限 |
| device / device_grant | device 主键 (a,device_id)，存自选名称、OS、client_version、registered_at、last_active、last_sync、revoked_at、version；grant 主键 (a,grant_id)，外键到设备，存状态、代际、刷新族及轮换代数 | 索引 (a,last_active)、(a,device_id,status)；授权码、刷新凭据按成熟库的哈希/受保护存储及唯一约束实现；撤销设备保留来源外键 |
| account_stream / change_log | stream 主键 a，存 epoch、head、可拉取下界；change 主键 (a,epoch,seq)，存 kind、resource_id、版本、操作及当时的白名单值或墓碑 | 账号行锁决定提交次序；按主键顺序翻页；保存当时的版本使重试不依赖可变当前行 |
| session / thread / session_thread | session (a,session_id)，thread (a,thread_id)，关联表 (a,session_id,thread_id)；记录父/分叉/原属线程、可证实的继承序号、子代理状态 | 反向索引 (a,thread_id,session_id)；父记录晚到先登记未解析关系，解析后校验无环；身份不足不填虚构父项 |
| observation | (a,device_id,observation_id)，含 source_rev、type、event_key 可空、状态、白名单证据、摘要、规则版本及可信度；保留撤回终态 | 索引 (a,event_key,state)、(a,thread_id,type)；仅当前有效版本参与投影；旧版摘要和变更可追溯 |
| ledger_event / event_evidence | event 主键 (a,event_key)，含 thread_id、turn_id、模型、时间、六项 Token、方法、可信度、状态、rule_version；evidence 联结事件与观测 | 外键均含 a，来源关联唯一。按 (a,thread_id,occurred_ms)、(a,model,occurred_ms) 查询；仅汇总已确认规范事件。按模型的视图从规范账本读取 |
| time_evidence | (a,device_id,observation_id) 引用观测；保存 thread、turn、区间、kind、证据类别或开始/结束边界 | end ≥ start；按 (a,thread_id,start_ms) 查询；重叠区间求并集后再计算时长 |
| project / task_group / group_member | 项目和任务组主键分别为 (a,project_id)、(a,group_id)；组可引用项目；成员有自己的 UUID，指定 session 或 thread，含 version、deleted_at | 成员恰有一种目标；活动成员对 (a,目标类型,目标 ID) 唯一，避免同一会话被重复分配。成员并发移动校验当前版本；删组/项目解除活动关联，并在同事务发布变更 |
| conflict | (a,conflict_id)，类型、关联资源、证据引用、基准和当前版本、受限的提议值、状态、处理人及时间 | 对同一未决冲突签名唯一；索引 (a,status,created_at)。事件争议保留来源，人工编辑冲突按版本解决 |
| operation_receipt | (a,epoch,device_id,op_id)，保存规范请求哈希、处理结果、资源版本和提交序号 | 同 ID 异载荷拒绝；来源修订高水位和资源版本长久保留，有效代际内保留回执，应对长时间离线重试 |
| snapshot / snapshot_page | (a,epoch,snapshot_id)，含 watermark、到期时间、页数和校验；页以 snapshot_id 和页号关联 | 同一一致读视图构建冻结页，只向所属账号的当前授权授予读取；过期重新生成 |
| audit / 部署控制 / schema_version | 只追加安全审计含账号、动作、结果、时间、内部设备 ID；独立备份的恢复控制记录含服务实例和代际；schema_version 含版本与迁移校验和 | 审计按账号与时间索引；限制运维读取。安全撤销同步持久写入独立恢复记录后方可确认。迁移使用独立角色及部署锁 |

部署使用版本化前向迁移并记录校验和。OAuth 授权库采用其受支持的存储模型，账号/设备外键统一映射到上述逻辑实体。设备在线状态由服务端时间计算，避免持久保存过期的在线标志。项目和组均默认只含 ID、用户显式名称及必要关联。

## 客户端 Outbox 与数据归属

独立同步 SQLite 使用自己的 application_id、schema_version 和迁移事务。`profile` 由可信 issuer、服务实例及不可变账号 sub 唯一确定；凭据保存在 Windows 受保护存储。下列本地表的主键和外键均以前述 profile 为前缀。

| 本地表 | 持久化内容及约束 |
| --- | --- |
| binding / scope | 授权设备、代际、本机数据根映射、用户选择的线程/历史范围和生效边界。根路径仅在本地；每一来源默认只能归属一个账号。跨账号的来源归属另用安装级唯一索引保护。 |
| manifest | 本机稳定来源槽（按类型和本地身份区分）、observation_id、最后已出队/已确认版本、当前白名单摘要、撤回状态、最近完整扫描代号。来源映射长期保留。 |
| outbox | 主键 op_id，来源/用户资源、source_rev 或 base_version、冻结的协议载荷、尝试次数、下次重试时间、状态和依赖；按状态/时间索引。已发送的操作永不原地改载荷。 |
| edit_journal | 主键 op_id；记录本机用户编辑的白名单基准、期望状态（含删除）、base_version、确认的服务端版本和代际。ACK 后仍保存各资源最后已确认意图及尚未解决的修改，供数据库回退后对账。 |
| replica / sync_state | 账号内规范资源副本、版本和墓碑；每账号有 epoch、pull_cursor、快照暂存命名空间；快照完成后一次切换。上传水位和下载游标独立。 |

1. 首次绑定以空范围开始。用户可明确选择存量 Session，或绑定该根之后新出现且归属明确的 Session。选择“从现在起”时记录已存在会话清单作为边界，旧会话追加须另行选择。同一根切换账号时冻结旧范围，无法判定归属的记录留本地。拉回的云端资源只写 replica，防止再次进入采集上传流程。
2. 同步进程校验 v2 应用标识和版本，在一致只读事务中读取授权范围内的 Session、Event 的指定结构字段、Ledger、核对及时间投影；将按线程排序的白名单行和确定性摘要暂存至本地。初扫、启动、重放后和周期性全量对账覆盖全部授权线程，日常唤醒可优先处理变化线程。物理偏移、SQLite rowid、文件修改时间和进程内通知均不作为正确性游标。
3. 完整读取后，在同步库一个事务中与旧清单比较。新增/更改生成更高版本 upsert；完整扫描证实某项撤出已知投影时生成 retract；同时提交清单和 Outbox。对原先有效的条目出现矛盾时还需传递类型化的否定证据，保证其他设备持有旧观测时全局也能降级。仅在明确属于同一已校验来源与范围的完整快照里确认删除；读锁超时、库被替换/回滚、来源根离线、取消绑定及扫描中断均不得触发批量撤回。库更换/回滚转人工核实或新来源绑定。可用代际暂存与最后一次切换缩短事务，清除未完成的暂存。
4. 发送时按照来源版本和资源依赖排序，操作进入在途。确认事务将回执与 Outbox 状态一同落盘，随后可压缩已确认载荷；保留最新清单、来源墓碑和待解决用户意图供灾后核对。两个 SQLite 库没有跨库事务：读取后中断则重扫，提交 Outbox 后中断则重发。已确认源数据可以由最新快照再次导出。

完整性判据利用 v2 保留原始规范事件这一性质。在本地清单保留已观测的事件 ID 集合、源根绑定和数据库文件身份。完整读取中若旧事件仍在，且其账项消失或出现新反证，视为投影修订；若先前存在的事件本身消失、文件被替换或根映射变化，暂停该根的差分发布，保留上一次清单并提示重新核对。首次读取大型库可按线程构建暂存，只有同一一致视图全部完成才能判定缺项。

## 跨设备入账判定

| 证据 | 规范投影 |
| --- | --- |
| 两台设备记录同一原属线程和响应 ID | 对各来源核对轮次、六项向量、归属、源时间及继承边界。兼容观测共用一笔；明显矛盾留 conflict，先撤下受影响精确统计。模型证据不一致但用量已证实时可保留总量，模型桶为 UNKNOWN。源时间差单列核对；时间字段无法确认时不用于精确时段汇总。 |
| A/B 各自只有同一会话的一段 | 以事件集合的并集汇总；每台设备仍可查看自身来源。相同 Session、相同时间、同标题或相同用量本身都不足以去重。相同响应 ID 在无关线程独立，分叉继承关系有矛盾时隔离受影响副本。 |
| 仅旧式快照 | 要求原属逻辑线程、源中稳定 ordinal、计数流所属范围及继承边界可证。规范键采用另一个域 `ct.snapshot.v1` 与账号、原属线程、明确的流标识、ordinal；源时间、前驱/首次基线、本次与累计向量用于校验。若源不提供独立流标识，仅在线程内可证明单一连续有序流时才使用该线程作为流范围。序号碰撞、重置分段不明、基线缺失或未知出处，保留待核实观测。禁止由文件名、绝对偏移或相似时间补造身份。 |
| 旧快照与新响应重叠 | 服务端按账号内原属线程收齐双方可用的计量证据再核对。仅接纳本地已认可的 DERIVED 增量，且满足 v2 首次/连续差分、祖先排除及安全旧前缀条件。重复累计为零，匹配快照仅作旁证。若其他设备提供覆盖同段的响应或反证，撤销旧增量，再发布新投影；区间重叠或前驱顺序不明时保留可证响应，旧增量进待核实。 |
| 历史晚到、不同来源撤回 | 重算涉及的事件、祖先/子线程及覆盖区间。一个来源撤回只取消该来源；另一条有效独立证据可以保留账项。归属冲突、继承重复或同响应异值等反证对整个相关事件生效，未解决之前不能由任一过时来源重新确认为精确值。 |
| 无法确认或字段缺失 | OBSERVED 表示直接观测；DERIVED 表示有可复核增量证据；PARTIAL、UNKNOWN 单列。缓存读、写、推理缺失保留 null。以 total 汇总，缓存和推理只是拆分。无法证明为不同事件的待核实观测报告条数及来源，避免构造虚假的待核实 Token 合计。 |

用于旧前缀核对的证据包含线程/轮次、源时间/ordinal、累计流范围、前驱 ordinal 及向量、是否已知期初、继承关系、逐响应本次/累计向量和 v2 核对状态。只传枚举和定型计数；证据不足时即使本机可归属，也可在云端标为“跨设备待核实”。本机 Phase 1 分类及数字保留。

耗时按可信的开始/结束及 v2 已裁切的工作、暂停区间上传。执行时间取兼容证据的区间并集，重叠只算一次；对同线程跨机暂停/执行矛盾或时钟顺序异常的区段记未知。总历时从已证首尾边界求差，未知为总历时扣去互斥的活跃与暂停区间。缺首尾时标记不完整，仅展示已知边界。设备睡眠明细、心跳间隔和离线时长不作为任务执行证据。

## Push、pull 与恢复

**上传。** 客户端从握手取得 epoch、能力及批量上限。以下是一个完整的逐响应 upsert 请求示例。示例源 ID 取自脱敏夹具，设备和账号由授权上下文确定。数值单位为 Token 与 UTC 毫秒。

```json
{
  "protocol": 1,
  "epoch": "217fa883-d016-4a6b-bf86-52811fcb0386",
  "operations": [{
    "op_id": "5f40ffc6-9d3e-4601-bfb4-c58c11376786",
    "kind": "observation.upsert",
    "observation_id": "c731c07d-d9cc-4299-814c-731f42fd6846",
    "source_rev": 1,
    "fact": {
      "type": "response", "rule_version": "sqlite-v2",
      "thread_id": "thread-A", "session_id": "session-A",
      "turn_id": "turn-A", "response_id": "response-1", "ordinal": 58,
      "occurred_ms": 1700000014115, "model": "gpt-6.2-astra",
      "confidence": "OBSERVED",
      "usage": {"input":35874,"output":103,"cache_read":34560,"cache_write":0,"reasoning":0,"total":35977},
      "thread_cumulative": {"input":35874,"output":103,"cache_read":34560,"cache_write":0,"reasoning":0,"total":35977}
    }
  }]
}
```

upsert 的 fact 按 type 解析。response 提供逐响应计量；snapshot 提供前驱/本次/累计证据和核对枚举；lineage 提供源会话、父线程与继承序号；timing 提供一个边界或有界区间；quality 提供受影响的响应/来源引用和原因枚举。所有变体都使用同一套来源修订。observation.retract 只含 op_id、kind、observation_id、source_rev 和原因枚举；服务端保留该来源的版本墓碑。遇到尚无身份的负面证据时，通过可证明的线程或覆盖范围隔离相关旧快照，无充分依据的观测保持待核实。

同一请求先全量验证字段与限额，格式错误整批拒绝。随后逐 op 独立事务，故断连可能已有一部分提交。事务以固定顺序锁定账号流、验证存活授权/代际、查回执、核对来源修订、重算关联投影、分配账号提交序号，写入变更与回执后提交。撤销使用同一锁定边界。每个产生可见改变的 op 以一个序号发布包含所改资源的原子变更组，大型重算用有界的快照重置通知。回滚不发布序号；同一 op 重放不递增账号序号。样例响应如下。

```json
{"epoch":"217fa883-d016-4a6b-bf86-52811fcb0386","results":[
  {"op_id":"5f40ffc6-9d3e-4601-bfb4-c58c11376786","status":"applied","source_rev":1,"seq":41}
]}
```

同 op、同哈希返回原回执；同 op 异哈希返回 OP_ID_REUSE。来源修订相同且同摘要返回 duplicate，修订旧于现存高水位返回 superseded。相同修订异值进入冲突；较新版本是完整替代或墓碑，可覆盖缺失的低版本。业务冲突持久化后返回 recorded_conflict，客户端移出重试队列并保留待处理项。版本队列永不因超时当作成功。网络、429、5xx 采用带随机抖动的指数退避，建议 1 秒起、上限 5 分钟，遵守 Retry-After；重连唤醒一次。无效字段停放以便纠正，认证过期尝试一次刷新，撤销后冻结分区。

**下载。** 以当前 profile 的 epoch 和 after 游标取提交序号大于 after 的完整变更组，按 seq 升序。第一页固定 until=head，后续页携带同一上界；返回 next、has_more 和每组白名单资源版本/墓碑。每页在 replica 与游标的同一事务内应用，相同版本可安全跳过。中途崩溃从最后已落盘游标再读。上传回执的 seq 不推进 pull 游标。新提交留到下一遍读取，空页不越过未读取的组。服务端按账号序列化写入，避免先分配序号的事务后提交而漏读。

**快照。** 游标早于变更保留下界（初始建议 90 天）、代际不符或收到重置通知，进入重建。服务端冻结该账号截至 watermark 的规范数据、来源高水位、项目/任务组、未决冲突和必要墓碑；快照票据绑定账号、设备、代际、到期时间。客户端校验页数与摘要，原子替换 replica 和游标，保留本机 manifest、Outbox、待处理用户编辑，再从 watermark 之后追增量。快照过期则丢弃暂存重新开始。

**灾后和本地回滚。** 服务端从备份回退后必须切换 epoch 并重新授权。原机持有已恢复登记的设备身份时，需账号所有者重新批准、校验原绑定证明，显式签发新 grant 才可续用该来源命名空间；实际已解绑设备不得走此路径。复核完成前暂停上传。客户端把最新获准来源清单（含已 ACK 项与撤回墓碑）和云端本设备来源版本/哈希逐一比对，缺项/低版本重放；遇到本地备份较旧以云端高水位为准，禁止覆盖，新本地修改须先重读受信来源并产生更高版本。同版本异值记冲突。全新安装或无绑定证明时使用新 Device ID，强身份事件可跨设备去重，旧来源的撤回须经恢复核对。单纯重新登录不重建来源身份。

旧代际的项目更名、删除或成员编辑可能已经执行过且恢复点之后还有其他编辑。保留本地编辑意图和当时版本作恢复对账，禁止直接套用旧回执、补发旧删除或按客户端时间覆盖。新快照与保留意图有差异则列为恢复冲突，用户确认后针对当前版本提交新 op。若只有较早的备份且没有任何客户端/审计副本，报告不可恢复时间窗。
